# 프로젝트 실행 가이드

## 사전 요구사항

| 항목 | 버전 |
|------|------|
| Java | 21 이상 |
| Node.js | 18 이상 |
| Docker & Docker Compose | 최신 버전 (Docker 실행 시) |

---

## 1. 로컬 개별 실행 (개발 환경 권장)

개발 시 가장 간단한 방법입니다. H2 인메모리 DB가 자동으로 사용됩니다.

### 1-1. 백엔드 서비스 실행 (터미널 3개 필요)

프로젝트 루트에서 실행합니다.

```bash
# 터미널 1 - Auth Service (포트 8082)
./gradlew :auth-service:bootRun

# 터미널 2 - Blog Service (포트 8081)
./gradlew :blog-service:bootRun

# 터미널 3 - Gateway Service (포트 8080)
./gradlew :gateway-service:bootRun
```

> **Windows 환경:** `./gradlew` 대신 `gradlew.bat` 또는 `gradlew` 사용

**실행 순서 주의:** Gateway는 blog-service, auth-service가 먼저 실행된 후 시작하는 것이 좋습니다.

### 1-2. 프론트엔드 실행 (포트 3000)

```bash
cd frontend
npm install
npm run dev
```

### 1-3. 접속 확인

| 서비스 | URL |
|--------|-----|
| 프론트엔드 | http://localhost:3000 |
| API 게이트웨이 | http://localhost:8080 |
| Auth Service (직접) | http://localhost:8082 |
| Blog Service (직접) | http://localhost:8081 |
| H2 콘솔 (auth) | http://localhost:8082/h2-console |
| H2 콘솔 (blog) | http://localhost:8081/h2-console |

## 2. Docker Compose 실행 (전체 환경)

PostgreSQL DB와 모든 서비스를 한 번에 실행합니다.

### 2-1. 기본 실행

```bash
# 프로젝트 루트에서
docker-compose up -d
```

### 2-2. JWT 시크릿 키 직접 지정 (권장)

```bash
JWT_SECRET=my-custom-secret-key-must-be-at-least-256-bits docker-compose up -d
```

또는 `.env` 파일 생성 후 실행:

```bash
# .env 파일 생성
echo "JWT_SECRET=my-custom-secret-key-must-be-at-least-256-bits" > .env

# 실행
docker-compose up -d
```

### 2-3. 로그 확인

```bash
# 전체 로그
docker-compose logs -f

# 특정 서비스 로그
docker-compose logs -f gateway-service
docker-compose logs -f blog-service
docker-compose logs -f auth-service
```

### 2-4. 종료

```bash
# 컨테이너 중지
docker-compose down

# 컨테이너 + 볼륨(DB 데이터) 삭제
docker-compose down -v
```

## 3. API 사용 예시

모든 요청은 게이트웨이(8080)를 통해 전달됩니다.

### 회원가입

```bash
curl -X POST http://localhost:8080/api/auth/signup \
  -H "Content-Type: application/json" \
  -d '{"username": "user1", "password": "password123"}'
```

### 로그인

```bash
curl -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username": "user1", "password": "password123"}'
```

### 게시글 목록 조회

```bash
curl http://localhost:8080/api/posts
```

### 게시글 작성 (인증 필요)

```bash
curl -X POST http://localhost:8080/api/posts \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer {JWT_TOKEN}" \
  -d '{"title": "제목", "content": "내용"}'
```

## 4. 환경변수 정리

| 변수 | 설명 | 기본값 (dev) |
|------|------|--------------|
| `JWT_SECRET` | JWT 서명 키 (256비트 이상 필수) | `playground-dev-secret-key-...` |
| `DATABASE_URL` | PostgreSQL JDBC URL (prod 전용) | H2 인메모리 사용 |
| `DB_USERNAME` | DB 사용자명 (prod 전용) | - |
| `DB_PASSWORD` | DB 비밀번호 (prod 전용) | - |
| `SPRING_PROFILES_ACTIVE` | 활성 프로파일 | `dev` |

> **주의:** JWT_SECRET은 모든 서비스(gateway, blog, auth)가 동일한 값을 사용해야 합니다.

---

## 5. 프로파일별 DB 설정

| 프로파일 | DB | 설정 방법 |
|----------|-----|-----------|
| `dev` (기본) | H2 인메모리 | 별도 설정 불필요 |
| `prod` | PostgreSQL | 환경변수로 주입 필요 |

로컬에서 PostgreSQL을 직접 테스트하려면:

```bash
SPRING_PROFILES_ACTIVE=prod \
DATABASE_URL=jdbc:postgresql://localhost:5432/playgrounddb \
DB_USERNAME=playground \
DB_PASSWORD=playground123 \
./gradlew :blog-service:bootRun
```

## 6. 빌드 (배포용 JAR 생성)

```bash
# 각 서비스 JAR 빌드
./gradlew :gateway-service:bootJar
./gradlew :blog-service:bootJar
./gradlew :auth-service:bootJar

# 프론트엔드 빌드
cd frontend && npm ci && npm run build
```

빌드 결과물 위치: `{서비스명}/build/libs/*.jar`
